# План: баланс, окно контекста, помощь, резюме диалога, аналитика

## Что выяснено из документации Kimi
- Окно контекста K3.1 Pro — 1 000 000 токенов.
- Баланс: `GET /v1/users/me/balance` (только Moonshot) — доступно, ваучеры, наличные, в USD. При балансе ≤ 0 запросы получают ошибку `exceeded_current_quota_error`.
- Оценка токенов до отправки: `POST /v1/tokenizers/estimate-token-count` (Estimate Tokens).
- Кэш контекста автоматический; `usage` может содержать кэшированные токены; TTL `5m` / `1h` через `prompt_cache_options.ttl`.
- Уровни рассуждения low/high/max (у API по умолчанию max, у нас High), есть быстрый вариант `kimi-k3.1-pro-highspeed` — модель не меняем, только упоминаем в справке.
- Лимиты аккаунта (RPM, TPM, параллельность) зависят от суммы пополнений — показываем только реальные ошибки 429.

## 1. Баланс Kimi
- Серверная функция `getKimiBalance` (только владелец): запрос к balance, ответ — три числа и время проверки. Для kineticRouter и других адресов — честное «баланс недоступен у этого провайдера».
- Значок баланса в шапке: сумма в USD, опрос раз в 5 минут и сразу после каждого ответа. Жёлтый ниже $1, красный при ≤ 0 с подсказкой пополнить.
- Подробности (ваучеры/наличные) — в подсказке и в настройках.
- Ошибку `exceeded_current_quota_error` переводим в понятный текст «Закончился баланс Kimi».

## 2. Окно контекста
- Секрет `KIMI_CONTEXT_WINDOW` добавляю со значением 1000000 (из документации).
- Индикатор: «использовано / осталось» и процент; оранжевый от 80%, красный от 95% с советом начать новый диалог или сделать резюме.
- Оценка токенов черновика через Estimate Tokens по кнопке/с задержкой ввода — показывается как «≈», отдельно от фактического usage.
- Показ кэшированных токенов в подробностях ответа, если API их вернул.

## 3. Документация, подсказки, помощь
- `docs/kimi/` в проекте: сохранённая квикстарт-страница и страницы balance, estimate, errors, reasoning effort, context caching (markdown, с датой и ссылкой на источник).
- Страница `/help` (раздел «Помощь»): начало работы, уровни рассуждения, файлы и картинки, инструкции, контекст и баланс, резюме, экспорт/копии, ошибки и что с ними делать, горячие клавиши.
- Подсказки (tooltips) у ключевых кнопок и короткие «советы» на пустом экране нового чата; ссылка на помощь в меню и настройках.

## 4. Резюме диалога и следующие шаги (AI Gateway)
- Действие «Резюме и шаги» в меню диалога и в списке слева; выбор диалога — через этот пункт.
- Серверная функция: берёт сообщения диалога (с правом владельца), отправляет в Lovable AI Gateway (модель по умолчанию `openai/gpt-6-astra`, потоково, строгий JSON: `summary`, `action_items[]`). Kimi при этом не подменяется — это отдельная функция.
- Длинные диалоги ужимаются до лимита по символам (последние сообщения приоритетно), об этом пишем в результате.
- Результат в окне: резюме + чек-лист шагов, кнопки «Копировать» и «Вставить в чат». Сохраняется в таблицу резюме (владелец, диалог, текст, время), видно последнее.
- Ошибки 402/429 от Gateway — понятные сообщения, без повторов по кругу. Использует кредиты Lovable — это отмечаем в справке.

## 5. Аналитика
- События: `project.message_sent` (есть ли картинки/файлы, уровень рассуждения), `project.file_attached` (тип: image/text, количество), `project.reply_regenerated`, `project.conversation_exported` (формат: markdown/json/backup). Плюс `project.summary_generated`.
- Без текста сообщений, имён файлов и прочих личных данных.
- Регистрация в каталоге событий и проверка схемы.
